The proxy is designed to give a reliable and trusted connection to the network.
People can put up cloud instances which act as proxies to personal nodes.
This way the individual need not setup their own website to get trusted browser access to it.
Also users can use proxies to obfuscate their traffic.
They can contact other nodes directly without an outside observer knowing exactly who is making the request.
Since they all fall behind the same proxy IP.
There is ofcourse also the option for the user to connect directly to their node but only through native apps.
The browser cannot be used to do such a thing because the personal node does not support http.

Beyond this you can connect a proxy to personal node(s) directly within the same process
    by using the personal node as a library and calling its functions from within a proxy program.
Also you could just configure the provided proxy to use the default personal node setup.


The proxy at a low level is an http server that forwards packets to nodes.
It may also have authorization related functions to prevent unwanted access.
To reiterate it can also have direct access to node functionalities if it wishes.
In that case the remote node is accessed via loopback IP addr.
