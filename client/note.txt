    FILE SYSTEM DATA STRUCTURES:

        ( FEED || CHAT || MARKET ) BLOBS:
            Chained together via IDs( UserKey, (thread kind), blob_idx ) makes it deterministic.
            User data has starting blob indices.
            You allocate a blob then fill it, then allocate the next sequentially.

        PERMISSIONS:
            Blobs of UNORDERED [ H(Perm) + (REC || GIV) ] (33 bytes). 
                Blobs chained by IDs( UserKey, PERM(uint8), blob_idx )
                Perm data stored under hash.
            Retrieve blob, then request the specific perm data.
                You then send the RECIEVED perms and hash to the remote node when posting.
                Or revoke/append GIVE perms and send to remote node.
                Create new blobs when necessary.

        FINANCE DATA:
            Custom data structure.
            Probably has some header, and then history blobs.
            Or something like that.



SENDING A POST:
    Generate Key for the post.
    Hash and Encrypt Entire Post Meta, Media, Everything into a single blob.

    Hash ( encrypted Post & Cleartext Hash), then sign it.
    Send the encrypted Post & Cleartext Hash to server with signature.
        Server then saves that encrypted data under that hash.

    Take (key to encrypt, cleartext hash, and ciphertext hash).
    Encrypt key and clearHash with shared(derived) key with desired recipient.
    Send the encrypted key and hash along with the ciphertext hash and signature. 
    And of course the appropriate permission.

    Later the recipient can request the cleartext hash because they have permission to do so.
    Or we do some voucher system to prevent constant access.
